# 2026-07-11 批量审计结论

## 背景

对 Synthos/outputs/papers/ 下 80+ 篇论文进行全面参考文献审计。尝试了多种方法后得出以下结论。

## 失败的尝试

| 方法 | 结果 | 原因 |
|------|------|------|
| 子 Agent 逐一处理 33 篇 | 超时 | 600s 不够，每篇需 ~30s |
| literature.py 逐篇检索 | 超时 | 80 篇 × 30s = 40min |
| 子 Agent 写批量脚本 | 挂死 | 脚本内部 subprocess 调用卡住 |
| MedData pmid=1 占位 | 占位 PDF | 非真实 PMID 返回占位文件 |

## 成功的模式

| 方法 | 结果 | 关键 |
|------|------|------|
| 聚类检索（5 方向） | 2.5min | 替代 80 次逐篇搜索 |
| batch_fix_all.py | ~80% DOI, ~90% PDF | 单次遍历，Crossref 逐篇解析 |
| Sci-Hub CDN + 代理轮换 | 0% 429 | 518 代理随机，每请求换 IP |
| MedData 真实 PMID | 5/5 PDF | 必须真实 PMID，pmid=1 无效 |

## 关键数字

| 指标 | 之前 | 之后 |
|------|------|------|
| PDF 总量 | 464 | 887 |
| DOI 覆盖率 | 0% | 82% |
| 有 PDF 论文 | 29 | 81 |
| 无 PDF 论文 | 54 | 2 |

## 引用格式

- 71/83 论文使用内联 `thebibliography`（非 .bib 文件）
- 95% 内联引用无 inline DOI
- Crossref 自动匹配 ~30% 正确，需人工核对
- 管道必须同时处理 .bbl（29%）和内联（71%）

## 经验教训

1. **不重新造轮子** — 已有 literature.py，不写第二个检索实现
2. **delegate_task 不加微操** — 只传 goal 不加 context
3. **聚类而非逐篇** — 按主题聚类，1 次检索覆盖 ~15 篇论文
4. **DOI 自动补全可用** — Crossref API 虽有不匹配但大部分正确
5. **MedData 是下载平台非检索平台** — 需先通过 DOI→PMID 才能在 MedData 下载
