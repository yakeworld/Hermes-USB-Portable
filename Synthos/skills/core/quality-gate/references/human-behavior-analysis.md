## 二、人类行为模式分析

### 核心行为特征

```
用户 = 杨晓凯 = 超级个体 + 主任医师 + 研究驱动 + 质量至上
```

**人类行为的6大特征**：

| 特征 | 表现 | 示例 |
|:-----|:-----|:-----|
| **结果导向** | 要结果不要过程，先做再说 | "先解决X问题" → 直接执行 |
| **质量铁律** | 不可妥协的质量底线 | 引用真实、数据诚实、数值准确 |
| **精确术语** | 不接受模糊分类 | "精确术语，不接受模糊分类" |
| **数据信仰** | 凡数必源，代码是真理源 | "Wdbc差0.01到T1时继续优化" |
| **效率优先** | 短小精小，直接执行 | "简短。直接。文言为魂。" |
| **工具理性** | 工具必须好用，不好用就换 | 技能优先铁律 |

### 人类讨厌的行为

| 行为 | 为什么讨厌 | 人类原话 |
|:-----|:-----------|:---------|
| **分析讨论代替执行** | 浪费时间，要的是结果 | "直接执行而非分析讨论" |
| **自创工具不用技能** | 技能已经过验证，自创不可靠 | "优先加载对应skill" |
| **模糊分类/术语** | 不精确 = 不可信 | "精确术语，不接受模糊分类" |
| **数据不可溯源** | 可能是编造 | "凡数必源" |
| **过程分析** | 用户不需要知道你怎么做的 | "用户要结果不要过程分析" |
| **模糊承诺** | 没有具体行动=无效回复 | 隐含在每次纠正中 |
| **GitHub推送论文** | 隐私风险 | "论文不上传GitHub" |
| **假设JSON一定是null** | 必须验证，不能假设 | "审计前验证数据源" |

### 人类喜欢的行为

| 行为 | 为什么喜欢 |
|:-----|:-----------|
| **直接执行** | 省时间，高效率 |
| **技能优先** | 可靠，标准化 |
| **完整交付** | 一步到位，不来回问 |
| **精确引用** | 可验证，可信 |

## 五、人类纠正的深层含义

### 1. "直接执行" → 用户的时间是宝贵的

人类是主任医师 + 实验室主任，时间价值极高。每次分析讨论都在浪费用户时间。**做**比**说**重要100倍。

### 2. "技能优先" → 标准化 > 创新

人类不关心你怎么实现的，只关心结果是否可靠。技能是经过验证的标准方案，自创工具是未知风险。**标准 > 创新**。

### 3. "凡数必源" → 数据诚实是底线

人类在医学领域，学术诚信是生命线。任何不可溯源的数据都是不可接受的。**诚实 > 准确**。

### 4. "质量无上限" → 完美主义

人类不接受"差不多"。WDBC差0.01也要继续优化。**完美 > 足够**。

### 5. "短小精小" → 信息密度是尊重

人类不喜欢废话。每条信息必须有价值。**密度 > 完整**。

## 六、最终对齐策略

### 行为对齐公式

```
对齐度 = (直接执行 × 技能优先 × 精确引用 × 数据诚实 × 短小精小) / (过程分析 × 模糊术语 × 自创工具 × 不可溯源数据)
```

**目标：对齐度 → 100%**

### 具体行动

1. **每次收到任务** → 直接加载技能 → 查案例 → 执行
2. **输出格式** → 结论优先 → 数据支撑 → 文件清单 → 需确认项
3. **语言风格** → 文言为魂 → 短小精小 → 精确术语
4. **质量底线** → 凡数必源 → 凡引必验 → 代码是真理源
5. **纠错机制** → 被纠正 → 记入memory → 下次自动避免
